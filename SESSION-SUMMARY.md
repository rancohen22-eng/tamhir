## 1. What the system does
Internal, multi-user, Hebrew (RTL) web app that documents the full life-cycle of a
flight booking for Arkia, from request to ticketing, with an external travel agent
("Teltos") participating by email. Flow:

1. **Initiator** opens a request (minimal fields; route, pax, date).
2. Request is opened to an **open pool of agents**; any agent may quote.
3. **Agent** submits a price quote (+ screenshot), optionally flags **LOW COST**;
   an agent may also open an **urgent** agent-initiated quote.
4. One of the **department's approvers** approves/rejects (any of several approvers;
   can approve directly from the email).
5. **Agent** issues the ticket (PNR + ticket document).
6. **Cancellation:** before ticketing = immediate; after ticketing = two-step
   (request → agent confirms).

Supporting features: per-booking file attachments, an audit **timeline** ("who did
what, when"), **finance** dashboard with filters/export, bilingual **email
notifications** with branded HTML + approve-from-email, **in-app bell** notifications,
an **admin** console (departments, approvers, users, airports, wet operators,
currencies, usage gauges), **login log + attempt log**, an **email read-log** (open
tracking), login **brute-force lockout**, a PWA (add-to-home-screen) with an optional
client-side **biometric unlock**, and an in-app user guide.

## 2. Technology & versions
**Current production stack (in `bookings/`):**
- **Oracle Autonomous Database** (Always Free) — schema + all business logic in
  **PL/SQL** packages (`api_pkg`, `booking_pkg`).
- **Oracle REST Data Services (ORDS)** — exposes the REST API (module `arkia.api`,
  base path `/ords/arkia/api/`) and serves the SPA.
- **Oracle APEX** libraries used from PL/SQL: `APEX_MAIL` (email), `APEX_JSON`
  (responses), `APEX_WEB_SERVICE` (base64/BLOB), `APEX_UTIL`.
- **Front end:** a single-file **vanilla-JS SPA** (`bookings/app/index.html`, no
  framework), Hebrew RTL, PWA (web manifest + service worker), **WebAuthn** for the
  optional biometric local gate. Served from ORDS as base64 (`install_ui.sql`).
- **Email:** **OCI Email Delivery** SMTP relay (`smtp.email.il-jerusalem-1.oci.
  oraclecloud.com:587`, STARTTLS) via `APEX_MAIL`. Display sender is a Gmail address
  configured as an OCI "Approved Sender" (not Gmail SMTP).
- **Password hashing:** salted **SHA-256** (`STANDARD_HASH`, per-user random salt).
- **CI/CD:** **GitHub Actions** (`.github/workflows/deploy-bookings.yml`) deploys on
  push using **SQLcl 26.2** over an Oracle wallet. A manual `prod-reset.yml` exists.
- **Build helpers:** Python 3 (`gen_ui.py` embeds the SPA into SQL; `gen_guide.py`
  builds the guide; Chromium used at build time to render the guide PDF).

**Migration package (in `port-kit/`)** — a self-hosted re-platform target:
- **Node.js 20** + **Express 4.21.2**, **pg 8.13.1**, **bcryptjs 2.4.3**,
  **nodemailer 6.9.16**; **PostgreSQL 14+**; Docker (`node:20-alpine`).

> Note: the portal's own rules (SQL Server + Windows auth + a C# `PortalAuditMiddleware.cs`)
> imply an **ASP.NET Core** host — neither the Oracle system nor the Node port-kit
> matches that yet. See `PORTAL-COMPLIANCE-PROPOSAL.md`.

## 4. How to run / build
**Current (Oracle):** push to the deploy branch → GitHub Actions runs SQLcl against
the ADB and executes `install_api.sql` → `03_booking_pkg.sql` → `install_ui.sql`,
recompiles packages, and verifies they are VALID. App is then at
`/ords/arkia/api/app`. One-time email setup: run `deploy/email_setup.sql` (after
filling SMTP credentials). After editing the SPA: `python3 api/gen_ui.py` regenerates
`install_ui.sql`.

**Self-host (port-kit):** create a PostgreSQL DB → run `schema.postgres.sql`,
`seed.postgres.sql`, and `\copy airports.csv`; `cd server && cp .env.example .env`
(fill DB + SMTP) → `npm install && npm start` (or `docker build` from `port-kit/`).
App at `/api/app`.

## 5. Screens (and what each does)
| Screen | Who | Purpose |
|---|---|---|
| **Login** | all | Username/password; 30-day session; biometric unlock option; brute-force lockout. |
| **Bookings** (list + KPI) | all | Bookings visible to the user, with status, route, LOW COST / urgent badges. |
| **Booking detail** | all | Full details, attachments, **timeline** audit, and role-based action buttons (quote/approve/reject/ticket/cancel). |
| **New booking** | initiator/approver | Open a request (route via **type-ahead** airport search, pax, time, wet operator; optional file). |
| **Urgent quote** | agent | Agent-initiated quote into a chosen department (flagged red). |
| **Finance** | finance/admin | Dashboard + filters (date/dept/status) + Excel/CSV export. |
| **Admin** | admin | Usage gauges; edit **departments**; **approvers per dept** (several each); **users** (+create sends welcome email); **wet operators**; **airports**; **currencies**. |
| **Login log** | admin | Successful logins + **login attempts** table (username/IP/result/time). |
| **Email log** | admin | Sent emails with **read status + read time** (open-tracking pixel). |
| **Notifications (bell)** | all | Unread counter; list; per-user email opt-out. |
| **Guide** | all | In-app branded user guide (also a PDF). |

## 6. Data model (main tables / key fields)
- **departments** (dept_id, dept_code, name_he/en, is_active)
- **roles** (role_code) · **user_roles** (user_id, role_code) — ADMIN/INITIATOR/APPROVER/AGENT/FINANCE
- **app_users** (user_id, username, full_name, **email**, dept_id, pref_lang, is_active,
  notify_email, **password_hash**, **password_salt**)
- **dept_approvers** (dept_id, approver_user_id) — multiple approvers per department
- **agents** (agent_id, user_id, agency_name, contact_email, contact_phone, logo_blob)
- **currencies**, **statuses**, **wet_operators**, **airports** (iata, names, country)
- **bookings** (booking_id, dept_id, initiator_id, agent_id, approver_id, status,
  open/departure/ticketing dates, price, currency, **pnr**, pax_count, pref_time,
  origin/dest IATA, low_cost, urgent, quote_notes, trip_details, cancel fields)
- **booking_files** (file_kind QUOTE_SCREENSHOT/FINAL_TICKET/OTHER, filename, mime, **file_blob**, uploaded_by)
- **booking_status_log** (booking_id, from/to status, action_by, action_at, note) — audit
- **notifications** (user_id, booking_id, message, is_read) · **notif_templates** (status × role × he/en)
- **report_templates** (owner_id, columns_json, filters_json)
- Runtime/security tables: **api_sessions** (token, user_id, expires_at),
  **login_log** (username, login_at), **login_attempts** (username, **ip**, success, at),
  **booking_action_tokens** (token, booking_id, action, expires, used),
  **email_log** (token, recipient, kind, subject, sent_at, opened, opened_at, open_count)

## 8. Open / broken / caveats
- **Email read-tracking is best-effort only** (Apple Mail Privacy / image-blocking
  clients can mark "read" early or never) — indicative, not proof.
- **Biometric** login is a **client-side local gate** over the stored session token,
  not server-verified WebAuthn (acceptable for an internal tool; noted for review).
- **Password hashing is salted SHA-256** (fast hash). The port-kit already upgrades to
  **bcrypt**; recommend the same on the portal build.
- **`prod_reset.sql` has not been run** — test/sample data may still be in the Oracle
  DB. It could not be triggered via CI (the GitHub App lacked `actions: write`).
- **port-kit has TODO endpoints** not yet implemented: `bookings/edit`,
  `agent/quote/create`, `admin/user/update`, `admin/user/delete`, `admin/resetpw`,
  and the `GET /api/act` approve-from-email page.
- A **default temporary-password literal** is present in the seed/package files
  (location only in `SECRETS-INVENTORY.md`); must be rotated/removed before go-live.
- The repo also holds **two unrelated apps** (`index.html` pricing, `loans/`) that are
  **not** part of this system and are out of scope for the portal onboarding.
- The operational "actual performance" screen the user asked about earlier (fuel,
  tails, FT/BT, fleet split) belongs to a **different system not in this repo**.
